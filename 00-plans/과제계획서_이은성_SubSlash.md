## 1. 과제 개요

**SubSlash**는 사용자가 매월 반복적으로 지출하는 구독 서비스를 한눈에 관리하고, 실제 이용 빈도와 비용을 바탕으로 구독의 가치를 판단할 수 있도록 돕는 웹 서비스이다.

단순한 구독 목록 관리에 그치지 않고 **1회 사용 단가(Cost-Per-Use), 결제 전 체크인, 해지 직통 링크, 공유 구독의 실부담액, 해지 후 누적 절약액**을 연결하여 사용자가 불필요한 구독을 발견하고 실제 해지까지 이어갈 수 있도록 설계한다.

서비스의 핵심 방향은 **‘구독을 기록하는 서비스’가 아니라 ‘구독을 정리하도록 행동을 유도하는 서비스’**를 만드는 것이다.

## 2. 개발 배경 및 문제 정의

### 2.1 문제 상황

- OTT, 음악, 생산성 도구, 클라우드 등 구독형 서비스가 증가하면서 소액의 반복 결제가 누적되고 있다.
- 사용자는 자신이 어떤 서비스를 얼마나 자주 사용하는지와 실제 월 지출액을 동시에 파악하기 어렵다.
- 구독을 해지하려고 해도 서비스별로 해지 경로가 다르고, 일부 서비스는 여러 단계의 메뉴를 거쳐야 한다.
- 가족·지인과 공유하는 구독은 카드 청구액과 실제 본인 부담액이 달라 단순 지출 집계만으로는 정확한 판단이 어렵다.

### 2.2 개발 필요성

기존의 구독 관리 방식은 주로 ‘무엇을 구독하고 있는가’를 보여주는 데 초점을 둔다. SubSlash는 여기에 **사용량 → 비용 체감 → 유지/주의/해지 판단 → 실제 해지 → 절약액 누적**이라는 흐름을 결합한다.

이를 통해 사용자가 자신의 소비 패턴을 이해하고 행동으로 옮길 수 있는 능동형 구독 관리 경험을 제공한다.

## 3. 개발 목표

1. 사용자가 회원가입 없이도 구독을 등록하고 즉시 서비스를 사용할 수 있도록 한다.
2. 구독별 월 비용과 이용 횟수를 바탕으로 1회 사용 단가를 계산하여 비용을 직관적으로 체감하게 한다.
3. 결제 전에 간단한 사용량 체크인을 제공하여 장기간 사용하지 않은 구독을 발견하도록 한다.
4. 주요 구독 서비스의 실제 해지 경로를 제공하여 ‘판단’에서 ‘해지’까지의 마찰을 줄인다.
5. 공유 구독의 실제 개인 부담액을 반영하여 지출 및 절약액을 정확하게 계산한다.
6. 해지로 발생한 절약액을 누적하고 시각화하여 사용자가 구독 정리의 결과를 확인할 수 있도록 한다.

## 4. 주요 기능

### 4.1 구독 관리

- 구독 서비스명, 요금, 결제 주기, 결제일 등의 정보를 등록·수정·삭제한다.
- 월간·연간 결제를 구분하여 다음 결제일과 D-day를 계산한다.
- USD 등 외화 구독은 사용자가 설정한 환율을 적용하여 원화 기준으로 확인한다.

### 4.2 Cost-Per-Use 체감 엔진

- 결제일 이전에 최근 이용 횟수를 묻는 체크인을 제공한다.
- 이용 횟수와 실제 부담액을 이용해 1회 사용 단가를 계산한다.
- 결과에 따라 유지·주의·해지 권고의 상태를 시각적으로 표현한다.

### 4.3 해지 직통 링크(Kill-Switch)

- 주요 국내외 구독 서비스의 해지 링크와 단계별 해지 안내를 제공한다.
- 실제 해지 화면으로 바로 연결되는 링크와 서비스 진입 화면으로 연결되는 링크를 구분한다.
- 해지 과정에서 사용자가 놓치기 쉬운 다크 패턴을 간단한 가이드로 안내한다.

### 4.4 공유 구독 분담

- 가족·지인과 공유하는 구독의 참여 인원 및 개인 부담금을 관리한다.
- 균등 분할이 아닌 경우 실제 부담액을 직접 입력할 수 있도록 한다.
- 정산 시 사용할 문구를 자동 생성하여 복사할 수 있도록 한다.

### 4.5 Saved Pot

- 해지한 구독으로 절약한 금액을 누적한다.
- 누적 절약액으로 구매 가능한 현실적인 보상 단위를 시각화한다.
- 실제 절약액을 초과하는 과장된 보상을 표시하지 않도록 한다.

### 4.6 선택적 알림 및 캘린더

- 기본 사용 경험은 브라우저 로컬 저장소를 기반으로 제공한다.
- 사용자가 알림을 선택한 경우에만 이메일 알림에 필요한 최소 정보를 서버에 미러링한다.
- 결제일을 ICS 캘린더 피드로 제공하여 기존 캘린더 앱에서 알림을 받을 수 있도록 한다.

## 5. 차별화 방향

| 구분 | 일반적인 구독 관리 | SubSlash |
|---|---|---|
| 핵심 관점 | 구독 목록 및 지출 관리 | 사용 가치와 해지 행동 관리 |
| 사용량 | 직접 기록하거나 미제공 | 체크인 → 1회 사용 단가 |
| 해지 | 사용자가 직접 검색 | 해지 경로 및 단계 안내 |
| 공유 구독 | 총 결제액 중심 | 실제 개인 부담액 반영 |
| 성과 | 현재 지출 확인 | 해지 후 누적 절약액 시각화 |
| 개인정보 | 계정 중심 저장 | 비회원·로컬 우선 + 알림 선택형 서버 미러 |

## 6. 시스템 구성 및 기술 스택

프론트엔드와 서버 기능을 하나의 웹 애플리케이션으로 구성하고, 모노레포 구조를 이용하여 웹 앱과 공유 패키지를 관리한다. 데이터의 기본 경험은 localStorage를 사용하고, 알림·계정 등 서버가 필요한 기능만 별도로 분리한다.

| 영역 | 기술 |
|---|---|
| Framework | Next.js 15 (App Router) |
| Language | TypeScript |
| UI | Tailwind CSS 4 |
| State | Zustand + localStorage |
| Database | Turso (libSQL) + Drizzle ORM |
| Notification | Resend |
| Deployment | Vercel |
| Monorepo | Turborepo + pnpm |
| Testing | Vitest + Playwright |

## 7. 데이터 및 보안 설계 방향

- 비회원 기본 사용을 지원하여 사용자가 자신의 구독 정보를 별도 계정 없이 관리할 수 있도록 한다.
- 알림 기능을 선택한 경우에만 이메일 등 알림에 필요한 최소 정보만 서버에 저장한다.
- 비밀번호는 복호화 가능한 암호문이 아닌 scrypt 기반 해시로 저장한다.
- 데이터베이스 접근은 Drizzle ORM의 파라미터화된 쿼리를 사용하여 SQL Injection 위험을 줄인다.
- 세션 및 동기화 토큰은 원문을 서버에 저장하지 않고 해시 기반으로 관리한다.

## 8. 개발 및 검증 계획

1. **요구사항 및 UX 정리** — 핵심 사용자 흐름과 화면 구조 확정
2. **핵심 도메인 구현** — 구독·결제일·환율·분담금 계산 로직 구현
3. **핵심 UX 구현** — 대시보드, 체크인, Cost-Per-Use, 해지 링크, Saved Pot 구현
4. **서버 기능 구현** — 계정, 선택형 알림 미러, 이메일, ICS 캘린더 구현
5. **품질 검증** — 단위/통합 테스트와 Playwright E2E 테스트를 통한 주요 사용자 시나리오 검증
6. **배포 및 문서화** — Vercel 배포, README·설계 문서·테스트 결과 정리

## 9. 테스트 및 품질 기준

- 계산 로직은 월간/연간 결제, 외화 환율, 공유 분담 등 경계 조건을 포함하여 단위 테스트한다.
- 인증·데이터 저장 기능은 실제 입력값을 기준으로 통합 테스트한다.
- 회원가입 없이 시작 → 구독 등록 → 체크인 → 비용 확인 → 해지 → 절약액 반영의 핵심 흐름을 E2E로 검증한다.
- 결제일 미설정, 연간 구독, 공유 구독 등 예외 상태가 UI에서 잘못된 숫자로 표시되지 않는지 검증한다.

## 10. 기대 효과

- 사용자가 반복 지출을 단순 목록이 아닌 ‘사용 가치’ 관점에서 파악할 수 있다.
- 구독 해지에 필요한 탐색 및 절차 부담을 줄여 실제 행동으로 연결할 수 있다.
- 공유 구독을 포함한 개인의 실질적인 구독 비용을 더 정확하게 파악할 수 있다.
- 해지로 발생한 절약액을 누적하여 구독 정리의 결과를 지속적으로 확인할 수 있다.
- 로컬 우선 구조를 통해 불필요한 개인정보 수집을 줄이고 필요한 기능에 한해 서버 기능을 선택적으로 제공할 수 있다.
