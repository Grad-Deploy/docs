## IV. 회의 내용

### 1. 중간발표 일정 및 목표 범위 논의

중간발표는 2026년 5월 27일로 확정되었으며, 현재 Jira 백로그 기준 20개 하위 업무 항목이 모두 `해야 할 일` 또는 `진행 중` 상태임을 확인하였다. Task 3의 SCRUM-21~24는 이미 진행 중 상태로, 해당 항목들은 발표 전까지 시연 가능한 수준으로 완성하기로 하였다.

### 2. Task 1 (Argo CD 운영 환경 및 관리자 검증) 논의

이은성이 담당하는 Task 1은 Argo CD admin 대시보드 기반의 관리자 검증 환경 구성을 목표로 한다. 별도 관리자 페이지를 개발하지 않고, 기존 Argo CD UI에서 `Application` / `ApplicationSet` / `AppProject` 전체 상태를 확인하는 방식으로 범위를 확정하였다. GHCR private repo 인증 및 장애 상태별 명령 정리가 핵심 검증 항목으로 논의되었다.

### 3. Task 2 (데모데이 및 외부 주소 노출) 논의

이혁제가 담당하는 Task 2는 데모데이 당일 외부 접속 가능한 URL을 안정적으로 노출하는 것을 목표로 한다. Ingress 또는 zrok/tunnel 방식의 장단점을 비교 검토하여 노출 방식을 확정하기로 하였다. 발표 당일 장애 상황에 대비한 복구 절차 문서(SCRUM-20) 작성이 필수 항목으로 강조되었다.

### 4. Task 3 (비용/크레딧 및 Guardrail 완성) 논의

이온이 담당하는 Task 3은 Cluster Advisor 기반 리소스 차단 및 Guardrail 기능의 완성을 목표로 한다. SCRUM-21~24가 이미 진행 중이며, CPU/Memory request 기반의 비용 계산 기준과 `imagePullSecrets`, Ingress, selector 등 Guardrail 항목 보강이 주요 논의 사항이었다. 발표용 장애 시나리오(SCRUM-25)는 중간발표 전날까지 초안을 완성하기로 하였다.

### 5. Task 4 (프론트 + 백 + DB 테스트 서비스 템플릿) 논의

고민서가 담당하는 Task 4는 Mini Board(게시판) 서비스를 기반으로 프론트엔드, Node.js 백엔드, PostgreSQL DB가 통합된 테스트 서비스 템플릿을 구성하는 것을 목표로 한다. Argo CD를 통한 실제 배포 테스트(SCRUM-30)까지 완료하는 것을 발표 전 최종 목표로 설정하였다. 환경변수, `Secret`, `ConfigMap` 연결 검증(SCRUM-29)이 배포 테스트의 선행 조건임을 확인하였다.
