## TASK-1.1: Argo CD Admin Access Runbook

```md
# <JIRA-KEY>: Argo CD admin access runbook

## Context
Grad-Deploy will not build a separate admin page. The operator uses the Argo CD admin dashboard.

## Goal
Create or update the runbook for accessing Argo CD as admin and checking the full deployment state.

## Scope
- Document how to get the initial admin password.
- Document how to expose or access the Argo CD server URL.
- List the admin dashboard areas to check: Applications, ApplicationSets, Projects, Repositories, Settings.
- Add a short presentation-day checklist.

## Do not touch
- OAuth, GitHub SSO, or RBAC implementation code.
- Mini Board test service code.
- Cost or Guardrail logic.

## Acceptance criteria
- A teammate can follow the runbook and log into Argo CD as admin.
- The runbook explains what the admin should verify in Argo CD.
- No unrelated code changes.
```

## TASK-1.2: ApplicationSet Auto-Generation Verification

```md
# <JIRA-KEY>: Verify ApplicationSet auto-generation

## Context
Grad-Deploy uses ApplicationSet, not App of Apps, as the final deployment structure.

## Goal
Verify that ApplicationSet watches `k8s/projects/<proj>/services/*` and creates service-level Applications.

## Scope
- Confirm AppProject is applied before ApplicationSet.
- Confirm ApplicationSet is applied successfully.
- Add or document a verification flow for creating `<proj>-<service>` Applications.
- Record Argo CD UI or kubectl verification steps.

## Do not touch
- DemoDay UI.
- Mini Board implementation.
- Cost/Guardrail rules.

## Acceptance criteria
- Argo CD shows `<proj>-<service>` Applications generated by ApplicationSet.
- No `argo-parent-app.yaml` or App-of-Apps dependency is required.
- Verification commands or screenshots are recorded.
```

## TASK-1.3: GHCR and Private Repository Authentication Verification

```md
# <JIRA-KEY>: Verify GHCR and private repo authentication

## Context
Private GitHub repositories and GHCR private images can fail in Argo CD or Kubernetes without proper credentials.

## Goal
Verify and document the authentication path for private repo sync and GHCR image pulls.

## Scope
- Check Argo CD Repository Secret flow.
- Check GHCR imagePullSecret flow.
- Verify pods do not fail with ImagePullBackOff.
- Document recovery steps for authentication failures.

## Do not touch
- OAuth login implementation.
- DemoDay UI.
- Mini Board application behavior.

## Acceptance criteria
- Argo CD can read the private repo.
- Kubernetes can pull GHCR images.
- Recovery steps for private repo and GHCR failures are documented.
```

## TASK-1.4: End-to-End Deployment Checklist

```md
# <JIRA-KEY>: Create E2E deployment checklist

## Context

## Goal
Create a repeatable E2E checklist for the full deployment loop.

## Scope
- Include GitHub push verification.
- Include GitHub Actions success verification.
- Include GHCR image push verification.
- Include Argo CD sync/health verification.
- Include Pod Ready and external URL verification.

## Do not touch
```

## TASK-1.5: Failure-State Diagnosis Commands

```md

## Goal
Document diagnosis commands for common failure states.

## Scope

- OAuth or RBAC code.

## Acceptance criteria
- Each failure state has cause, command, and recovery direction.
- Commands are verified or marked as expected commands for the demo cluster.
```
